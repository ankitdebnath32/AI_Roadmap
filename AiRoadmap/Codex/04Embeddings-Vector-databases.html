Project 1

Semantic Document Search Engine

Build a Spring Boot API that ingests documents, creates traceable chunks, embeds them, stores them in PostgreSQL + pgvector, and returns ranked passages with provenance.

Document API
Parser + chunker
Embedding client
PostgreSQL + pgvector
Search API
Requirements and data flow
  • POST documents is idempotent and records document version, checksum, tenant, ACL, and embedding contract.
  • A worker parses and chunks, embeds in batches, upserts chunks, and removes stale versions.
  • GET search embeds the query, applies server-derived tenant/ACL filters, retrieves top-k, and returns source spans.
  • Expose health, ingestion status, retrieval trace ID, and no-answer behavior.

Flow: upload -> validate -> queue -> parse -> chunk -> embed -> upsert -> query -> authorize -> embed -> retrieve -> return evidence.

Folder structure and implementation

src/main/java/com/acme/search/embedding
src/main/java/com/acme/search/retrieval

src/main/resources/db/migration
  1. Create document and chunk tables with vector dimension, metadata, offsets, and unique stable IDs.
  2. Implement tokenizer-aware recursive chunking behind a versioned Chunker interface.
  3. Batch embedding calls with retry, timeout, truncation metrics, and dead-letter handling.
  4. Start with exact SQL search; add HNSW when load tests require it.
  5. Return ranked evidence DTOs. Keep LLM generation outside this first project.
Testing and interview explanation
  • Unit: chunk boundaries, stable IDs, overlap, metadata validation, dimension mismatch.
  • Integration: Testcontainers PostgreSQL/pgvector, filtered nearest-neighbor query, update and deletion.
  • Relevance: versioned labeled queries with recall@k and MRR.
  • Load: corpus scale, concurrency, selective filters, exact vs HNSW recall and p95.
  • Security: tenant/ACL isolation and malicious request metadata.

Interview: "I separated ingestion and query contracts, kept exact search as a quality baseline, enforced authorization in the datastore query, and introduced ANN only after measuring recall-latency tradeoffs."

Project 2

Hybrid Search API with Azure AI Search

Build a Spring Boot retrieval API using keyword and vector queries in one request, RRF fusion, metadata security filters, and semantic ranking.

Spring REST API
Query embedding
Hybrid request
RRF + semantic ranker
Evidence response
Architecture and implementation steps
  1. Create a versioned index with searchable content/title, filterable tenant/ACL/language/date fields, and a vector field with matching dimensions.
  2. Configure vector profile and semantic configuration; ingest chunk text, vectors, and provenance.
  3. Authenticate with managed identity/RBAC. Never expose admin keys to clients.
  4. Send search text and vectorQueries together, k large enough for reranking, an OData authorization filter, queryType semantic, and a small final top.
  5. Map results into evidence DTOs with captions, source IDs, RRF/semantic scores where exposed, and a trace ID.
Request sketch
POST /indexes/kb-v2/docs/search?api-version=<stable-version>
{
  "search": "how do I rotate an API key",
  "vectorQueries": [{"kind":"vector","vector":[...],"fields":"contentVector","k":50}],
  "filter": "tenantId eq 'acme' and aclGroups/any(g: g eq 'engineering')",
  "queryType": "semantic",
  "semanticConfiguration": "kb-semantic",
  "top": 8
}
Testing and interview explanation
  • A/B lexical, vector, hybrid, and hybrid+semantic on the same labeled query set.
  • Test exact IDs, paraphrases, mixed queries, no-answer, multilingual queries, and highly selective ACL filters.
  • Measure recall@50 before reranking, nDCG/MRR after reranking, p95 latency, throttling, cost, and index freshness.
  • Test preFilter/postFilter behavior and confirm no unauthorized document appears in candidates or logs.

Interview: "I used parallel lexical and vector retrieval because identifiers and paraphrases require different signals, RRF because raw scores are incomparable, semantic ranking for precision, and server-side ACL filtering at retrieval time."

Practice Workbook

Cheat Sheets & 14-Day Plan

Embeddings

  • Representation is model/version specific.
  • Match query/document modes and metric.
  • Normalize only as required.
  • Dimensions affect cost, not guaranteed quality.
  • Similarity is relatedness, not truth.
  • Evaluate domain queries before migrating.

Vector databases

  • Exact search is the quality baseline.
  • ANN trades recall for speed.
  • HNSW: memory/build for strong read performance.
  • IVF: cluster lists + query probes.
  • Filter placement changes recall.
  • Plan reindex, backup, deletion, and freshness.

Retrieval

  • Chunking defines what can be found.
  • Hybrid covers paraphrases and exact terms.
  • Rerank only candidates you retrieved.
  • Enforce ACLs in the query.
  • Track recall@k, MRR/nDCG, latency, cost.
  • Trace every stage before blaming the LLM.
