Azure OpenAI architecture

What is it?

A managed model-serving boundary in Microsoft Foundry: your Azure resource and deployment expose model inference endpoints while Azure supplies capacity, networking, safety controls, identity integration, and operational metrics.

Why does it exist?

It turns a foundation model into an Azure-governed dependency that can fit enterprise identity, regional processing, private networking, quota, and procurement controls.

How does it work?

The client calls a deployment name through an endpoint. The deployment binds a model version and deployment type to capacity. Requests pass authentication, quota enforcement, content filtering, inference, and telemetry.

When should I use it?

Use it when the application needs OpenAI models with Azure governance, billing, network controls, or data-residency choices.

When should I not use it?

Do not treat the portal playground as production architecture or assume the resource region always equals the processing location; deployment type determines routing.

How do I implement it?

Provision with IaC, choose a deployment type deliberately, authenticate the workload with Microsoft Entra ID, place model calls behind your backend, and expose neither keys nor model endpoints to browsers.

How do I debug it?

Separate DNS/network, 401 identity, 403 role, 404 deployment name, 429 capacity, content-filter, and model-response failures. Correlate provider request IDs with your trace ID.

How do I explain it in an interview?

Azure OpenAI is a governed inference plane: resource plus model deployment plus endpoint, protected by Entra/RBAC and network controls, with quota and safety policies around model execution.

Implementation sketch
// The browser calls your API, never the model endpoint directly.
Client -> APIM -> Backend -> Azure OpenAI deployment

Model deployment

What is it?

A named serving configuration that binds a model and version to a capacity and data-processing mode. Application code sends the deployment name in the model field.

Why does it exist?

Model identity alone does not reserve capacity or define routing, lifecycle, throughput, and compliance behavior.

How does it work?

Global Standard, Data Zone Standard, regional Standard, provisioned, priority, and batch options trade price, latency variance, residency, and throughput. Availability is model and region dependent.

When should I use it?

Start with Global Standard for broad general availability unless residency or predictable throughput imposes a different choice; use provisioned throughput for sustained mission-critical load.

When should I not use it?

Do not hard-code a model marketing name where a deployment name is expected. Do not buy provisioned capacity before load testing the token mix.

How do I implement it?

Create blue/green deployment names, externalize the active deployment, pin lifecycle policy, record version, and canary model upgrades against an evaluation set.

How do I debug it?

404 usually means endpoint/deployment mismatch. 429 can be token rate, request rate, or capacity. Compare observed input/output tokens and latency against deployment quota.

How do I explain it in an interview?

A deployment is the operational contract around a model: version, name, processing geography, throughput class, quota, and upgrade strategy.

Implementation sketch
AZURE_OPENAI_ENDPOINT=https://<resource>.openai.azure.com
AZURE_OPENAI_DEPLOYMENT=chat-prod-v2

Chat and completion concepts

What is it?

Chat APIs accept role-tagged messages; the newer Responses API offers a richer, unified interaction model. Legacy text completions are prompt-in/text-out and are not the default for modern chat models.

Why does it exist?

Message structure preserves instruction roles and conversation turns. Responses-style APIs support evolving features without forcing everything into one assistant message.

How does it work?

Your backend assembles system/developer policy, user input, history, retrieved context, and tool results; the service returns text, structured data, tool requests, or streamed events.

When should I use it?

Use Responses for new applications when the selected Azure model and SDK support it; use Chat Completions for existing systems and supported workloads.

When should I not use it?

Do not assume parameters or response shapes are identical across APIs or reasoning models. Some reasoning models ignore or reject temperature-style controls.

How do I implement it?

Wrap the SDK behind an application port so request shape, deployment, retries, and telemetry can evolve independently of domain code.

How do I debug it?

Log API family, deployment, sanitized message roles, finish reason, token usage, and provider request ID. A valid HTTP response can still contain refusal or truncated output.

How do I explain it in an interview?

Chat Completions models a transcript; Responses is the newer unified API surface. I isolate either behind a backend adapter because capabilities are model- and version-dependent.

Implementation sketch
// Version-dependent sketch
var result = await chatClient.CompleteChatAsync(messages, options, ct);

Embeddings

What is it?

Dense numeric vectors that encode semantic features of text. Similar meanings tend to be closer under the metric configured by the retrieval index.

Why does it exist?

They make semantic retrieval possible when query wording differs from source wording.

How does it work?

An embedding deployment maps text to a fixed-dimensional vector. Documents and queries must use a compatible model and vector-space configuration.

When should I use it?

Use for semantic or hybrid retrieval, clustering, deduplication, and similarity features.

When should I not use it?

Do not use embeddings as encryption, ground truth, or a replacement for exact keyword matching and authorization filters.

How do I implement it?

Normalize inputs, batch ingestion, retain model/version metadata, validate dimensions, and reindex when changing incompatible embedding spaces.

How do I debug it?

Dimension errors are explicit; silent relevance loss comes from model mismatch, poor chunks, language/domain mismatch, or comparing with the wrong metric.

How do I explain it in an interview?

Embeddings are learned coordinates for semantic similarity; production correctness requires the same embedding space, measured retrieval quality, and metadata filters.

Implementation sketch
var vector = await embeddingClient.GenerateEmbeddingAsync(chunk, ct);
// Store vector + chunk + source + ACL metadata.

Structured output

What is it?

A model response constrained to JSON or a supplied JSON Schema rather than free-form prose.

Why does it exist?

Backend systems need validated contracts, not optimistic JSON parsing from natural language.

How does it work?

Supporting models use response-format/schema controls. Schema-constrained decoding narrows valid outputs, but semantic correctness still requires validation.

When should I use it?

Use for extraction, routing, classifications, commands, and domain DTOs.

When should I not use it?

Do not assume every model/API supports the same schema subset. Do not skip range, business-rule, or authorization validation.

How do I implement it?

Version the schema, reject unknown unsafe actions, deserialize strictly, validate business invariants, and retry only when the failure is recoverable.

How do I debug it?

Capture validation paths and finish reason; distinguish truncated JSON, unsupported schema, refusal, and valid-but-wrong values.

How do I explain it in an interview?

Structured output improves syntactic reliability with a schema; the application still owns semantic validation and side effects.

Implementation sketch
{ "type":"json_schema", "json_schema": { "name":"Ticket", "strict":true, "schema": { ... } } }
Knowledge check

Function calling

What is it?

A model capability that selects a declared function and proposes typed arguments. The model does not execute your method.

Why does it exist?

It translates natural-language intent into an application-controlled operation boundary.

How does it work?

The request includes function descriptions and schemas; the response may contain a call. Your orchestrator validates, authorizes, executes, then submits the result for the next model turn.

When should I use it?

Use for bounded operations such as lookup, calculation, workflow initiation, or domain commands.

When should I not use it?

Do not expose arbitrary reflection, raw SQL, or high-impact operations without confirmation and policy checks.

How do I implement it?

Keep schemas narrow, validate arguments, map tool name to an allowlisted handler, apply timeout/idempotency, and return compact typed results.

How do I debug it?

Trace model choice, proposed arguments, validation, handler latency, outcome, and the continuation turn without logging secrets.

How do I explain it in an interview?

Function calling is constrained intent generation; application code remains the executor and security authority.

Implementation sketch
if (!toolRegistry.TryGet(call.Name, out var handler)) throw new PolicyException();
await handler.ExecuteAsync(Validate(call.Arguments), ct);

Tool calling

What is it?

The broader orchestration pattern where models request one or more capabilities such as functions, search, code execution, or external services.

Why does it exist?

It lets the model gather current facts or act through controlled interfaces rather than fabricate outcomes.

How does it work?

A loop alternates model decisions and trusted tool results until a final answer or budget boundary is reached.

When should I use it?

Use when user intent varies and tool choice benefits from semantic reasoning.

When should I not use it?

Do not use an open-ended loop for deterministic workflows, and never treat model-generated arguments as trusted.

How do I implement it?

Define an allowlist, per-tool scopes, maximum turns, cost/time budget, idempotency keys, audit events, and human approval for consequential tools.

How do I debug it?

Inspect the state machine: available tools, selected tool, arguments, observation, repeated calls, termination reason, and policy denials.

How do I explain it in an interview?

Tool calling is a controlled state machine around model-proposed actions, with policy, validation, execution, observation, and termination owned by code.

Implementation sketch
for (var turn=0; turn<MAX_TURNS; turn++) { decide(); validate(); execute(); observe(); }

Streaming

What is it?

Incremental delivery of model output events, usually over server-sent events from Azure to the backend and then to the client.

Why does it exist?

It lowers perceived latency by improving time to first token, although total generation work is similar.

How does it work?

The client consumes deltas until a terminal event, then assembles final content and usage metadata. Tool events and structured outputs require event-aware handling.

When should I use it?

Use for interactive chat and long answers where early feedback matters.

When should I not use it?

Do not stream directly from the provider to an untrusted browser or parse partial JSON as complete.

How do I implement it?

Proxy with cancellation, heartbeat, backpressure, bounded buffers, disconnect propagation, and a final persistence event.

How do I debug it?

Measure time to first byte/token separately from total latency. Test client disconnects, mid-stream errors, partial UTF-8, and proxy buffering.

How do I explain it in an interview?

Streaming improves perceived latency and changes failure semantics: partial output may already be visible, so cancellation, assembly, and telemetry matter.

Implementation sketch
await foreach (var update in chatClient.CompleteChatStreamingAsync(..., ct))
    await sse.WriteAsync(update, ct);

Model selection

What is it?

Choosing a model and deployment based on measured task quality, latency, price, context, modalities, tool support, and regional availability.

Why does it exist?

The largest model is rarely the best system choice; architecture and workload determine value.

How does it work?

Build an evaluation set, set minimum quality and safety gates, then compare candidates under representative prompt, retrieval, concurrency, and token distributions.

When should I use it?

Use smaller models for routing/extraction where they pass gates; reserve larger or reasoning models for complex tasks.

When should I not use it?

Do not select from a leaderboard alone or assume every generation parameter applies to every model family.

How do I implement it?

Create a model capability registry and route by task. Store deployment configuration outside code and support fallback only when semantics remain acceptable.

How do I debug it?

Segment failures by model, prompt version, task class, region, and input length. Compare regressions against a fixed evaluation baseline.

How do I explain it in an interview?

Model selection is a constrained optimization problem: meet quality and safety first, then minimize latency and cost under operational limits.

Implementation sketch
route(task) => task.IsExtraction ? smallStructuredDeployment : reasoningDeployment

Tokens

What is it?

The model-native units used for input, output, context accounting, quota, latency, and consumption billing.

Why does it exist?

Character count and request count poorly predict model workload.

How does it work?

A tokenizer splits text into model vocabulary units. Input includes instructions, history, retrieved context, tool schemas, and sometimes hidden protocol overhead.

When should I use it?

Track tokens per feature, tenant, prompt version, and outcome.

When should I not use it?

Do not estimate multilingual or code tokens with a simple characters/4 rule for capacity planning.

How do I implement it?

Preflight large requests with the model-appropriate tokenizer, reserve output headroom, cap retrieved context, and record returned usage.

How do I debug it?

When cost or 429s spike, inspect token histograms, repeated context, verbose tool schemas, conversation growth, and retry duplication.

How do I explain it in an interview?

Tokens are both the context budget and a major throughput/cost unit; production services govern them before and after each call.

Implementation sketch
inputTokens = instructions + history + retrievedChunks + toolSchemas;
assert(inputTokens + outputBudget < contextLimit);

Context limits

What is it?

The maximum token budget a model can process for request input plus generated output, with exact rules varying by model and API.

Why does it exist?

Attention and serving resources are finite; oversized requests fail or force truncation.

How does it work?

All prompt components compete for the window. Larger windows do not guarantee equal attention or answer quality across every included fact.

When should I use it?

Use budgeting, retrieval, summarization, and conversation compaction to send the smallest sufficient context.

When should I not use it?

Do not fill the window because it exists or silently remove system instructions and recent turns.

How do I implement it?

Allocate explicit budgets by component, preserve policy and recent intent, rank evidence, and fail clearly if required evidence cannot fit.

How do I debug it?

Log component token counts and truncation decisions. Reproduce missing-context failures with the exact assembled request.

How do I explain it in an interview?

A context window is a hard capacity boundary, not model memory; good systems budget and rank information before inference.

Implementation sketch
budget = limit - outputReserve - systemTokens - toolTokens;
context = rank(chunks).TakeTokens(budget);
Knowledge check

Design prompt: Name the identity, data boundary, capacity limit, observability signal, and failure behavior for Context limits.

Interview anchor: A context window is a hard capacity boundary, not model memory; good systems budget and rank information before inference.

Temperature

What is it?

A decoding control that reshapes token probabilities before sampling; lower values sharpen and higher values flatten the distribution.

Why does it exist?

It provides a quality-diversity trade-off for model families that expose it.

How does it work?

Logits are scaled before softmax. It does not add knowledge, reasoning, or truthfulness.

When should I use it?

Use low variance for extraction and factual workflows; evaluate moderate variance for ideation.

When should I not use it?

Do not rely on temperature for deterministic contracts, and do not send it to models that do not support it.

How do I implement it?

Treat decoding settings as model-specific configuration and evaluate repeated runs.

How do I debug it?

Verify the parameter was accepted, the model supports it, and other nondeterminism such as backend changes or retrieval is not being blamed on temperature.

How do I explain it in an interview?

Temperature changes sampling entropy, not the model weights or evidence. Schema and validation solve different problems.

Implementation sketch
// Capability-gated setting
if (model.SupportsTemperature) options.Temperature = 0.2f;
Knowledge check

Design prompt: Name the identity, data boundary, capacity limit, observability signal, and failure behavior for Temperature.

Rate limits

What is it?

Runtime enforcement of request and token throughput for a deployment/resource subscription scope.

Why does it exist?

Shared capacity must be protected and fairly scheduled.

How does it work?

A request can be rejected before inference when request-per-minute, token-per-minute, concurrency, or dynamic capacity limits are exceeded.

When should I use it?

Design for bounded queues, concurrency limits, retry-after, jitter, and admission control.

When should I not use it?

Do not retry every 429 immediately or independently in every service replica.

How do I implement it?

Use a distributed limiter, token estimate, priority lanes, exponential backoff with jitter, and a retry budget smaller than the request deadline.

How do I debug it?

Read headers and error payload, distinguish quota from transient capacity, and graph attempted versus accepted token rate.

How do I explain it in an interview?

Rate limiting is an online traffic-shaping problem; I combine admission control, bounded retries, workload priorities, and capacity planning.

Implementation sketch
if (!await limiter.AcquireAsync(estimatedTokens, ct)) return TooManyRequests();

Quotas

What is it?

Administrative capacity allocations that bound what can be deployed or consumed, scoped by model/deployment offering, region, and subscription.

Why does it exist?

Azure capacity is finite and deployment families have separate pools.

How does it work?

Quota is assigned to deployments, while observed rate limits enforce use. Provisioned throughput uses PTUs and separate capacity rules.

When should I use it?

Review quota before region/model commitments and before load tests; request increases with forecast evidence.

When should I not use it?

Do not confuse a quota approval with guaranteed zero throttling on standard capacity.

How do I implement it?

Maintain quota inventory as operational metadata, alert on headroom, and create a tested multi-deployment strategy where residency permits.

How do I debug it?

Compare requested deployment capacity, assigned quota, current consumption, offering, and region. A quota can exist in the wrong pool.

How do I explain it in an interview?

Quota is the administrative ceiling; rate limits are the runtime gate. Both must be modeled separately.

Implementation sketch
capacityPlan = forecast.PeakTokensPerMinute * safetyFactor;

15 security questions

01How do you prevent provider credentials reaching the browser?

Terminate at your backend; use Entra for client auth and managed identity from workload to Azure services.

02How do you enforce tenant isolation in RAG?

Trusted identity claims become pre-ranking filters over propagated tenant/ACL metadata; test deny cases.

03What is the role of private endpoints?

They constrain network reachability; they do not replace identity, RBAC, or application authorization.

04How do you handle prompt injection in retrieved documents?

Treat documents as untrusted data, isolate instructions, restrict tools, validate outputs, and test malicious corpus items.

05How do you protect PII in prompts and telemetry?

Minimize, classify, redact/tokenize where possible, define retention and access, and avoid raw logging by default.

06How do you secure function/tool calls?

Allowlist tools; validate schemas; authorize each action; constrain egress; use idempotency, budgets and human approval.

07API key leaked: what now?

Revoke/rotate, identify exposure and usage, preserve incident evidence, move to identity, and remove from history/artifacts.

08How should groups be used in search filtering?

Resolve validated Entra membership, store principal metadata on every chunk, and construct escaped search.in filters server-side.

09How do you separate administrators from runtime callers?

Different Entra principals and least-privilege control/data-plane roles, PIM for humans, IaC for assignments.

10How do you secure document upload?

Authorize, size/type limit, quarantine and scan, parse in isolation, validate metadata, and publish only after successful processing.

11How do you prevent data exfiltration through tools?

Scope tool result fields, enforce resource ownership, egress allowlists, output DLP, and audit consequential access.

12What should an audit event contain?

Actor, tenant, action/tool, resource ID, policy decision, trace ID, outcome and timestamp without secret or unnecessary content.

13How do you address indirect prompt injection?

Assume all external content is adversarial; never elevate document instructions over system policy or tool permissions.

14How do you protect secrets used by legacy dependencies?

Key Vault, managed identity access, short cache, rotation, no logs, network controls, and a migration plan.

15What is secure failure behavior?

Fail closed on auth/filter uncertainty, preserve tenant boundaries, expose safe errors, bound retries, and retain sanitized diagnostics.
