01
Security

Prompt injection

What is it?

Adversarial instructions embedded in user-controlled text that try to override the application policy or redirect model behavior.

Why does it exist?

Models interpret instructions and data through the same token channel, so untrusted content can influence control flow.

How does it work?

Direct attacks arrive in the user request; indirect attacks arrive through retrieved pages, files, tool output, memory, or messages.

When should I use it?

Threat-model every application that combines untrusted text with privileged context, retrieval, tools, or secrets.

When should I not use it?

Do not treat a stronger system prompt, delimiter, or detector as a complete security boundary.

How do I implement it?

Separate policy from data, label untrusted context, minimize capabilities, validate every sensitive action in deterministic code, and test adversarial corpora.

How do I debug it?

Trace which content influenced the decision, reproduce with the exact assembled prompt, inspect tool authorization, and verify the policy failed closed.

How would I explain it in an interview?

Prompt injection is confused-deputy risk in a probabilistic interpreter; containment comes from least privilege and deterministic authorization, not prompt wording alone.

Security

Indirect prompt injection

What is it?

Malicious instructions hidden in documents, web pages, emails, images, tool results, or other content an AI system consumes.

Why does it exist?

An attacker may not control the user but can poison content that the application retrieves later.

How does it work?

The model reads external content as context and can mistake embedded text for an instruction, causing leakage, unsafe tool calls, or policy evasion.

When should I use it?

Apply whenever RAG, browsing, email, files, memory, or third-party tool output enters a model context.

When should I not use it?

Do not trust content because it came from an authenticated repository or passed a malware scanner.

How do I implement it?

Treat retrieved text as hostile data, strip active markup, preserve provenance, use scoped tools, require confirmation for consequential actions, and run injection test documents.

How do I debug it?

Record source IDs and context order, then determine whether the malicious chunk was retrieved, followed, and able to reach a privileged capability.

How would I explain it in an interview?

Indirect injection is stored or reflected instruction injection through the data plane; authorization must remain outside the model.

Security

Jailbreaking

What is it?

A family of techniques that tries to bypass model or application safety constraints through framing, encoding, role-play, multi-turn pressure, or adversarial transformations.

Why does it exist?

Safety classifiers and instruction following are probabilistic and can be attacked adaptively.

How does it work?

Attackers search for prompts that shift priorities or disguise prohibited intent; success can vary by model, version, language, and context.

When should I use it?

Red-team systems exposed to untrusted users or high-risk domains and combine model safety with application policy.

When should I not use it?

Do not promise jailbreak-proof behavior or use model refusal as authorization.

How do I implement it?

Classify intent, constrain use cases, moderate input/output, remove unnecessary capability, monitor abuse patterns, and provide escalation/kill switches.

How do I debug it?

Compare failures by model/prompt version and language; retain sanitized attack metadata and rerun a fixed adversarial suite after changes.

How would I explain it in an interview?

Jailbreaking targets safety behavior; defense is layered risk reduction and capability containment, not a magic prompt.

Security

Data leakage

What is it?

Unauthorized disclosure of prompts, retrieved content, model outputs, memory, logs, embeddings, tool results, or cross-tenant data.

Why does it exist?

GenAI systems aggregate many data paths, and a model can restate any sensitive information placed in its context.

How does it work?

Leakage can occur through excessive retrieval, prompt injection, verbose errors, caching, telemetry, shared state, or overprivileged tools.

When should I use it?

Model data flow and classification before production; test cross-user and cross-tenant access explicitly.

When should I not use it?

Do not place data in a prompt merely because the model provider contract is acceptable; the application still controls exposure.

How do I implement it?

Minimize context, filter before retrieval, isolate tenants, redact logs, scope cache keys, apply DLP, and validate citations/output against authorized sources.

How do I debug it?

Reconstruct principal, filter, retrieved IDs, context, cache key, tool calls, and output; treat cross-tenant leakage as a security incident.

How would I explain it in an interview?

Data leakage is an end-to-end information-flow failure; the model is only one hop in the path.

PII

What is it?

Information that identifies or can be linked to a person, including combinations of otherwise ordinary fields.

Why does it exist?

Prompt, trace, feedback, and evaluation pipelines can create new copies of regulated data with unclear retention.

How does it work?

PII travels through input, retrieval, generation, persistence, telemetry, annotation, and third-party evaluation unless deliberately constrained.

When should I use it?

Use only when the business purpose and lawful basis require it; define minimization, access, location, retention, and deletion.

When should I not use it?

Do not log raw prompts or use production conversations as evaluation data by default.

How do I implement it?

Classify fields, redact or tokenize before model calls when possible, encrypt, restrict access, set TTL, honor deletion, and audit exports.

How do I debug it?

Trace data lineage across queues, caches, logs, datasets, backups, and vendor calls; verify deletion beyond the primary database.

How would I explain it in an interview?

PII protection is lifecycle data engineering: minimize, purpose-limit, secure, retain briefly, and prove deletion.

Secrets

What is it?

Credentials such as API keys, tokens, certificates, connection strings, and signing material.

Why does it exist?

Models and prompts are poor secret stores; generated or logged text can expose credentials broadly.

How does it work?

Secrets leak through source code, config, image layers, CI logs, prompt context, tool errors, and copied traces.

When should I use it?

Prefer managed identity; use a vault only for dependencies that still require secrets.

When should I not use it?

Never place secrets in prompts, system messages, client applications, model memory, or committed configuration.

How do I implement it?

Use Key Vault and workload identity, rotate automatically, scope permissions, scan code/images/logs, and redact error paths.

How do I debug it?

Revoke first, then identify exposure, affected calls and persistence; do not print a secret to verify it.

How would I explain it in an interview?

Secrets are high-impact configuration, not application data; eliminate them where identity can replace them.

Authentication

What is it?

Proof of the user, service, device, or workload identity making a request.

Why does it exist?

Prompts do not establish identity, and agent text cannot be trusted to say who the caller is.

How does it work?

OIDC/OAuth authenticates users; managed identity or workload identity authenticates services to Azure dependencies.

When should I use it?

Authenticate at the boundary and propagate only validated identity context.

When should I not use it?

Do not accept tenant, role, or user identity from request text or model output.

How do I implement it?

Validate issuer, audience, signature, expiry and nonce; map to an internal principal; use short-lived tokens and separate service identities.

How do I debug it?

Inspect token claims and clock, principal ID, audience, tenant, credential chain, and proxy header handling without logging tokens.

How would I explain it in an interview?

Authentication answers who; it must precede authorization and remain independent of model reasoning.

Authorization

What is it?

A deterministic decision that an authenticated principal may perform an action on a resource under current context.

Why does it exist?

A helpful model may propose an action that the caller is not allowed to perform.

How does it work?

Policy evaluates principal, tenant, resource ownership, action, state, and risk before retrieval or tool execution.

When should I use it?

Enforce on every resource access and tool call, including background tasks and retries.

When should I not use it?

Do not rely on a system prompt, earlier agent turn, UI hiding, or post-generation filtering.

How do I implement it?

Centralize policy, pass resource IDs rather than broad credentials, reauthorize at execution time, and audit allow/deny outcomes.

How do I debug it?

Reproduce with exact principal, resource and action; inspect stale group data, missing tenant context, and confused-deputy flows.

How would I explain it in an interview?

Authorization is a code-level security boundary; the LLM can suggest intent but cannot grant permission.

RBAC

What is it?

Role-based access control that maps principals to permitted operations at defined scopes.

Why does it exist?

It provides scalable least privilege and auditable separation between users, operators, deployers, and runtime identities.

How does it work?

Roles group permissions; assignments bind roles to principals at resource, tenant, project, or domain scope.

Use for coarse capability and administration boundaries, supplemented by resource-level checks.

When should I not use it?

Do not assign broad Contributor or shared admin roles to runtime agents.

How do I implement it?

Define data-plane roles in IaC, separate human and workload roles, use PIM for elevation, and review assignments periodically.

How do I debug it?

Check effective role, assignment scope, deny rules, token freshness, tenant, and propagation delay.

Tenant isolation

What is it?

Prevention of one customer accessing another customer’s data, state, tools, budget, or execution path.

Why does it exist?

RAG, caches, queues, vector indexes, agent memory, and background jobs create many cross-tenant leak paths.

How does it work?

Isolation can use dedicated resources, partitioned stores, or shared stores with mandatory tenant keys and pre-retrieval filters.

When should I use it?

Choose the isolation tier from risk, scale, compliance, noisy-neighbor, and cost requirements.

When should I not use it?

Never enforce tenant boundaries with prompt instructions or post-filtering a small result set.

How do I implement it?

Derive tenant from trusted identity, include it in every key/event/task, filter before ranking, isolate cache namespaces, and test negative access matrices.

How do I debug it?

Trace tenant ID from ingress to storage/retrieval/tool calls; search for missing-key code paths and asynchronous context loss.

How would I explain it in an interview?

Tenant isolation is an invariant carried through every synchronous and asynchronous boundary.

Tool permissions

What is it?

Least-privilege capabilities granted to model-invoked functions or external tools.

Why does it exist?

A tool transforms model output into real data access or side effects, increasing blast radius.

How does it work?

The orchestrator maps an allowlisted tool name to a scoped identity and validates action, resource, arguments, rate and approval.

When should I use it?

Use narrow read-only tools by default; split high-risk actions from low-risk lookup.

When should I not use it?

Do not expose raw shell, SQL, generic HTTP, or administrator credentials to an agent.

How do I implement it?

Create purpose-built schemas, per-tool identities, egress allowlists, resource ownership checks, budgets, and human approval for irreversible actions.

How do I debug it?

Trace tool selection, sanitized arguments, authorization, execution identity, dependency response, retries and final use.

What is it?

Input and output classification for harmful, prohibited, or policy-sensitive content.

Why does it exist?

Models can receive or generate content outside the product’s acceptable-use boundary.

Input validation

What is it?

Deterministic checks on request structure, size, type, encoding, identifiers, URLs, files, and business constraints before AI processing.

Apply at every trust boundary, including tool results and files from authenticated users.

Do not attempt to validate natural-language truth with regex or sanitize by deleting suspicious phrases alone.

Validate DTOs, MIME by bytes, file size/page count, URL schemes/hosts, Unicode normalization, and domain identifiers; quarantine risky uploads.

How do I debug it?

Record validation rule IDs and safe metadata; reproduce parser/encoding behavior and distinguish invalid input from safety policy.

What is it?

An orchestration pattern that contains model-proposed actions with policy, validation, execution controls, observation, and termination.

Why does it exist?

Tool calling creates agency; without controls, prompt injection can become unauthorized real-world action.

How does it work?

The model proposes a typed call; code validates schema, authenticates principal, authorizes resource, applies risk policy, executes idempotently, and returns bounded results.

When should I use it?

Use when natural-language intent benefits tool selection and the action can be safely constrained.

When should I not use it?

Do not use for simple deterministic workflows or irreversible actions lacking approval and compensation.

Inspect the state machine rather than only final text: proposal, arguments, policy, execution, observation, next decision and stop reason.

Token optimization

What is it?

Reducing unnecessary input and output tokens while preserving task quality.

Why does it exist?

Tokens drive context pressure, throughput, latency, and model cost.

How does it work?

Measure prompt, history, retrieval, tool schema and output separately; remove low-value repetition and cap generation.

When should I not use it?

Do not truncate blindly or optimize below the evidence needed for correctness.

How do I debug it?

Why does it exist?

It improves perceived latency and user control even when total generation time is unchanged.

20 questions

Performance

01How do you establish a latency budget?

Start from user SLO, allocate queue/gateway/retrieval/model/tools/persistence and reserve, then validate p95 under representative tokens.

02TTFT versus total latency?

TTFT governs perceived start; total governs completion/resource occupancy. Instrument both plus token counts.

03When should retrieval run in parallel?

Independent sources can run concurrently under bounded fan-out; authorization/filter must be consistent before merge.

04How do you reduce prompt tokens?

Remove repetition, shorten schemas/examples, summarize history and measure quality per component.

05How do you tune context size?

Use recall/rerank/context relevance/answer quality curves against token latency/cost.

06When does streaming not help?

Machine-consumed atomic JSON, very short responses, or buffered clients/proxies.

07How do you prevent cache stampede?

Single-flight/request coalescing, jittered TTL, admission and stale-while-revalidate where correctness permits.

08What invalidates an AI response cache?

Tenant/auth, prompt/model/tool/index/data/policy changes, freshness events and explicit purge.

09How do you benchmark models?

Representative task slices, repeated runs, quality/safety gates, token-normalized latency, cost and operational availability.

10How do batch APIs improve economics?

They decouple latency, improve utilization and may use discounted/separate capacity, with job lifecycle trade-offs.

11How do you size concurrency?

Load test token mix against provider/search quotas and connection/CPU/memory; cap below saturation knee.

12Why can fewer tokens hurt latency?

Over-compression can require retries/tools or reduce answer quality; optimize end-to-end successful task.

13What is critical path analysis?

Find the longest dependent span chain; parallel work outside it does not determine latency.

14How do reasoning models change budgets?

Capabilities/parameters and hidden/visible reasoning token behavior vary; use model-specific telemetry and output limits.

15How do retries affect performance?

They increase tail latency and load; measure retry tax and cap by remaining deadline.

16How does reranking affect latency?

Adds second-stage work but can reduce context and improve quality; evaluate net successful-task cost/latency.

17How do you optimize tool fan-out?

Planner decomposition, bounded concurrency, batch endpoints, cache reads and stop unnecessary calls.

18What is token-aware routing?

Select model/deployment/queue based on task and estimated token work within capability and policy gates.

19How do you test semantic cache threshold?

Label equivalent/non-equivalent query pairs by cohort and choose threshold for acceptable false-hit risk.

20What do you optimize first?

The largest measured contributor to failed or slow successful tasks, while preserving quality/security gates.

15 questions

Architecture

01Why keep Spring Boot and Python as separate services?

Use Java for enterprise API/domain/security integration and Python for AI ecosystem velocity; define a stable internal contract and avoid split authorization ownership.

02Where should APIM responsibilities stop?

At cross-cutting gateway policy: auth validation, products, limits, routing and observability; domain/agent logic belongs in services.

03Why are Blob and Search both needed?

Blob is durable source; Search is a rebuildable retrieval projection optimized for ranking.

04What state belongs in Cosmos DB?

Conversation/workflow/job/feedback/idempotency metadata with clear partition, TTL and source-of-truth rules.

05Why use Kafka in the capstone?

Durable decoupling, replay and load leveling for ingestion/long tasks/feedback; not for synchronous model token streaming.

06How do Java and Python share tracing?

W3C trace context over HTTP and Kafka headers, OpenTelemetry resource conventions and correlated release/model metadata.

07How do you avoid distributed monolith behavior?

Clear ownership, coarse contracts, async where appropriate, independent failure/deployability and no chatty cross-language calls.

08Where does authorization live?

Spring/domain policy and every resource/tool boundary; Python receives trusted scoped context but rechecks sensitive actions as needed.

09How do you separate online and ingestion capacity?

Different services, queues, quotas, autoscale signals and model deployments so backfills cannot consume chat SLO capacity.

10How does an outbox help?

Atomically store domain change and event intent, then publish asynchronously to avoid DB-success/Kafka-failure gaps.

11What is the index recovery strategy?

Rebuild from authoritative Blob/manifests and accepted metadata; version and switch after validation.

12How do you route models safely?

Capability registry and task policy choose pinned deployments; route/fallback versions are observed and evaluated.

13How do you expose streaming through Spring Boot?

Typed SSE endpoint, nonblocking upstream client, cancellation/backpressure, APIM buffering configuration and terminal events.

14What is the platform team contract?

Governed model/retrieval/tool/eval capabilities with identity, quota, telemetry and versioning; product teams own domain behavior.

15How do you prove disaster recovery?

Regular restore/rebuild/replay exercises measured against RTO/RPO, not a diagram or backup checkbox.
